## Сущность детали(Detail)

В своей работе я описывал авиационную деталь через Pydantic.
________________
Все поля создаются во время создания объекта, при некорректных полях объект не создается и в каталог не попадает.

| Поле            | Тип    | Правило                                                          |
|---|---|----|
|`id`| `str`| уникальный идентификатор,которы должен быть не пустым, не пробельным и единственным |
| `title`|`str` | название опрделенной детали может быть любое, но главное не пустое |
| `category`|`str` | категория детали строковое например: двигатель,шасси |
| `year`|`int` | год изготовления детяли. Есть строгие границы с 1904 до 2027 года |
| `serial_number`|`str` |серийные номер детали, который присваивают детали на заводе(аналог SER), обязательная длина от 1 до 15|
| `rule`|`Rule` | определенный класс, который указывает на критичность при поломке детали(аналог АП-25) |
___________
### Описание 2 полей, специально под авиационную деталь.
_____________
**serial_number** -  аналог SER из жизни, серийный номер детали, который завод ставит на каждую деталь
В российской и международной авиационной практике аббревиатура SER - Serial / Series (серия, серийность) — часть номера детали, указывающая на её исполнение, модификацию или производственную серию

**rule** - я взял за основу правила АП-25, которые активно используются в Российской авиации, а если точнее раздел A-0, в котором прописываются 5 значений при поломке той или иной детали. У меня эти значения:
1. CATASTROPHIC = "A",
2. HAZARDOUS = "B",
3. MAJOR = "C",
4. MINOR = "D",
5. NO_EFFECT = "E"

АП‑25 — это Авиационные правила «Нормы летной годности самолётов транспортной категории», устанавливающие требования для сертификации и безопасности транспортных самолётов.
_____________

| Метод                    | Что делает                                                                              |
|--------------------------|------------------------------------------------------------------------------------------|
| `add(item)` | добавляет деталь; если такой `id` уже есть — `DuplicateId`                               |
| `get(item_id`| возвращает деталь; если нет — `ObjectNotFound`          |
| `remove(item_id)` | удаляет деталь; если нет — `ObjectNotFound`      |
| `find_by_category(category)`  | все детали категории, без учёта регистра     |
| `find_by_name(query)`    | все детали без учёта регистра, ищет даже по части слова |
| `len(catalog)`    | количество деталей                            |
| `iter(catalog)`   | итерация по деталям в порядке добавления      |
| `item_id in catalog`  | есть ли деталь с таким `id`    |
__________

### Порядок итерации
_________
Все детали идут в том порядке, в котором мы их добавляем. Добавление удаленной детали заново вставит ее в конец. После загрузки в JSON порядок сохраняется.


### `save_file`

Записывает каталог в файл:

```json
{
   "format_version": 1,
   "items": [
      {
         "id": "A001",
         "title": "колесо",
         "category": "шасси",
         "year": 1967,
         "serial_number": "ASD1234",
         "rule": "D"
      }
   ]
}
```

Также важно учитывать формат версии файле. Он должен быть совпадать с нынешней версией

### `load_file`

Читает файл и заменяет содержимое каталога. Вначале весь документ читается, далее переносится во временный словарь там валидируется и только потом переходит в каталог. Если в документе была ошибка или некорректные данные, то главный каталог не измениться.

### Исключения

1. `IncorrectEssence` - неверная сущность при загрузке из файла
2. `DuplicateId` - айди дублируется
3. `ObjectNotFoun` - объект не найден
4. `UnsupportedFormatVersion` - версия формата не соответствует нынешнему
5. `BrokenFile` - сломанный файл
